# 한양대학교사범대학부속고등학교 통합 시스템 배포 원본

학교 Google 계정이 직접 소유하는 Google Sheets·Apps Script 백엔드 배포 자료입니다.

## 학적 통합 연결

`Academic.gs`는 학교 계정으로 접근 가능한 학적 원장을 읽어 학급·재학생·교과목·선택과목·분반을 반영합니다. Script Properties의 `ACADEMIC_SOURCE_SHEET_ID`에 학적 원장의 ID를 등록합니다. 공개 저장소와 일반 설정 응답에는 원장 ID를 넣지 않습니다. 11개 시트를 유지하며 연결용 열과 결시 신원 스냅샷 열만 안전하게 추가합니다(앱 3.1.1, 스키마 7).

고사 정보의 학년도·학기를 사용하며 접속·새로고침 시 5분 지난 자료를 갱신합니다. 관리자는 `학적 통합 연결 → 지금 동기화`로 즉시 갱신할 수 있습니다. 학생·학급·수강 과목 수정은 학적 통합에서 처리합니다. 시험 시간표·호실·결시·자리배치는 고사 통합에서 관리합니다. 중복 명단·번호·잘못된 과목 JSON·빈 원장이면 기존 자료를 유지합니다. 반복 동기화와 반 이동 시 기존 학생 ID와 시험 호실을 유지하고, 전출·자퇴 학생은 비활성화해 고사 기록을 보존합니다.

현재 교육과정으로 선택과목을 다시 해석하며, 확인되지 않은 과목이나 필수 선택 개수 오류가 있으면 전체 반영을 중단합니다. 기존 수강 명단을 부분적으로 지우지 않습니다. 중복 분반은 임의로 선택하지 않고 경고 건수로 표시합니다. 학년도·학기를 바꾸면 이전 기간 자료로 표시하고 새 기간 동기화 전에는 명단을 사용하는 고사 입력·배치를 차단합니다. 1~2월 기본값은 이전 학년도 2학기입니다.

실제 변경이 있는 동기화는 반영 직전 학교 소유 통합문서를 백업하고 비공개 `ACADEMIC_SYNC_JOURNAL`을 기록합니다. 중간 오류는 모든 대상 표의 복구를 각각 시도합니다. 복구가 끝나지 않거나 실행이 중단되면 조회·저장이 차단되며, 관리자 암호로 직접 진입하거나 다시 동기화하면 백업 복구를 먼저 시도합니다. 비공개 복구 속성과 백업은 임의로 삭제하지 마세요. 완료 요청은 최대 40개·6시간의 영속 receipt로 중복 반영을 방지합니다. 캐시 저장 실패는 이미 완료한 동기화를 실패로 바꾸지 않습니다. 변경 없는 갱신은 표를 재작성하거나 백업하지 않습니다.

고사 앱의 명단 조회와 쓰기는 같은 Script Lock으로 묶습니다. 이 잠금은 별도 학적 앱의 편집까지 잠그지는 않습니다. 학적 앱에서 대량 수정 중에는 수동 동기화를 피하고, 수정이 끝난 뒤 다시 동기화해 확인하세요. 실제 Google 실행시간·쿼터·25개 운영 동시 요청은 별도 검증 항목이며 로컬 합성 검사 통과만으로 보장하지 않습니다.

결시 신원 스냅샷은 새 제출과 다음 동기화 직전의 자료부터 보존합니다. 이미 과거 동기화로 바뀐 번호·이름을 자동으로 복원한다고 보장하지 않습니다. 개인 시간표는 현재 고사용이며 과거 학기 수강·호실의 재출력 보관소가 아닙니다. 공개 GET은 상태 확인만 하며 스키마 변경·동기화를 실행하지 않습니다.

## 들어 있는 파일

- `학교 정기고사 관리 시스템 - 배포용 원본.xlsx`: 11개 운영 시트와 사용설명서
- `apps-script/Code.gs`: 웹 앱 API, 인증, 세션, 저장 작업
- `apps-script/Config.gs`: 시트 이름, 열 구조, 권한 정책
- `apps-script/Repository.gs`: 시트 일괄 읽기·쓰기와 데이터 변환
- `apps-script/appsscript.json`: 시간대와 V8 실행 설정

기존 `.xlsx`는 초기 설치 자료이며 다시 만들 필요가 없습니다. 앱 3.1.1은 관리자 인증 후 기존 운영 시트의 누락된 열을 안전하게 추가하고 `설정.schema_version=7`을 기록합니다. `입력완료.revision`, `자리배치.seat_order`, `감사로그.actor_id`는 유지합니다. 학년별 교과목, 가정통신문 설정, 접속 사용자, 원안 포장 설정은 새 시트를 만들지 않고 `설정` 시트에 저장합니다.

## 설치

1. `.xlsx` 파일을 학교 Google Drive에 업로드합니다.
2. Google 스프레드시트로 열고 `파일 → Google 스프레드시트로 저장`합니다.
3. `확장 프로그램 → Apps Script`를 엽니다.
4. 기본 `Code.gs`를 교체하고 `Config.gs`, `Repository.gs`를 새 파일로 추가합니다.
5. 프로젝트 설정에서 매니페스트 파일 표시를 켠 뒤 `appsscript.json`을 교체합니다.
6. 시트를 새로고침하고 `정기고사 관리 → 초기 설정`을 실행합니다.
7. 학교명과 4자 이상의 관리자 암호를 입력합니다. 관리자 암호 원문은 저장되지 않습니다.
8. `배포 → 새 배포 → 웹 앱`에서 실행 사용자는 본인, 액세스 권한은 조직 정책이 허용하는 가장 넓은 범위로 설정합니다.
9. 웹 앱 URL을 프런트엔드 `public/assets/config.js`의 `API_URL`에 입력합니다.
10. 공개 화면의 `관리자 설정`으로 들어가 첫 접속 사용자와 숫자 4~6자리 개인 PIN을 등록합니다.

## 운영

- Apps Script 웹 앱은 반드시 학교 계정 소유로 배포합니다.
- 관리자 암호 변경은 시트 메뉴에서 실행합니다.
- 관리자 암호를 변경하면 세션 버전이 올라가 기존 관리자 세션이 모두 만료됩니다.
- 접속 사용자는 관리자 설정에서 추가·이름 수정·PIN 재설정·활성화·비활성화할 수 있습니다. 기존 PIN 조회와 완전 삭제는 지원하지 않습니다.
- 접속 이름을 수정하거나 PIN을 재설정하거나 사용자를 비활성화하면 해당 사용자의 기존 세션이 즉시 만료됩니다.
- `감사로그`에는 작업 시각·종류·건수·성공 여부와 비식별 사용자 ID만 기록하며 학생 이름과 접속 이름은 기록하지 않습니다.
- 학생 명단 엑셀 열은 `학년/반/번호/이름`입니다.
- 선택과목 엑셀 열은 `과목명/반/번호/이름/호실`입니다.
- 자리배치 수동 명단 열은 `반/번호/이름`입니다.
- 오래된 기록 정리는 프런트엔드 관리자 설정에서 기준일을 확인한 뒤 실행합니다.
- 결시 명단은 학급·교시 단위로 한 번에 제출합니다. 동시에 연 화면은 `revision` 충돌을 표시하고 최신 명단을 다시 읽습니다.
- 학생 명단 교체는 같은 학급·번호의 기존 학생 ID를 재사용합니다. 삭제 학생은 비활성화해 과거 결시 기록의 연결을 보존합니다.
- 선택과목 가져오기는 매칭하지 못한 원본 행 번호와 오류 코드를 반환하며, 오류가 한 건이라도 있으면 기존 명단을 건드리지 않습니다.
- 학년별 교과목은 한 학년에 최대 200개까지 저장하며, 과목명은 공백을 정리한 뒤 80자 이하·중복 없음 규칙을 적용합니다.
- 가정통신문 설정은 `학년도/학기/고사명/인사말/안내사항/발행일/발행 명의`를 한 묶음으로 검증해 저장합니다.
- 자리배치는 같은 모드·고사일·교시·학년·학급·과목·호실 조합을 다시 저장하면 기존 행을 갱신합니다.
- 자리배치 순서는 가로 순번(행 우선)과 세로 순번(열 우선) 중에서 선택하며, 기존 저장 자료에 순서 값이 없으면 가로 순번으로 불러옵니다.
- 원안 포장 과목은 기존 `시간표` 행을 기준으로 하며 대표교사, 답안지 종류, 포장일·시간대, 항목 revision을 같은 행에 보존합니다.
- 시간표 일괄 저장은 기존 ID의 원안 포장 필드를 유지하며 일반 시간표 입력값으로 해당 필드를 덮어쓸 수 없습니다.
- 원안 포장 설정은 `설정.exam_packaging_config_json`에 revision, 입력 마감, 슬롯 정원, 포장일, 시간행, 날짜·시간대별 교무 담당자를 저장합니다.
- 비밀 링크는 256비트 임의 토큰을 URL fragment로 전달하고 첫 접속 때 30분 미사용 만료 전용 세션으로 교환합니다. 원본 토큰은 다시 조회할 수 없습니다.
- 입력 마감 뒤 링크 사용자는 읽기 전용이며, 종료일 경과·폐기·재발급 시 기존 전용 세션도 즉시 만료됩니다.
- 포장 설정 변경으로 사용 중인 날짜·시간대가 사라지면 먼저 영향 건수를 반환하고, 관리자가 확인한 강제 변경에서만 기존 배정을 비웁니다.
- 같은 과목의 동시 수정은 항목 revision 충돌로 차단하고, 슬롯 정원 검사는 Script Lock 안에서 수행합니다.

## 보안 메모

- 사용자별 PIN은 각기 다른 임의 소금값과 Script Properties의 비공개 pepper를 적용한 SHA-256 해시로 저장됩니다. 관리자 암호도 임의 소금값을 적용한 해시만 Script Properties에 저장됩니다.
- 사용자·관리자 세션은 임의 토큰으로 발급되어 브라우저 `sessionStorage`와 Apps Script Cache에만 유지됩니다.
- 모든 쓰기 작업은 필수 `request_id`, 작업·권한별 Script Lock과 중복 방지 캐시를 함께 사용합니다.
- 프런트엔드는 동일 요청을 일시적 오류 때 최대 3회 재시도합니다.
- 접속 상태는 사용자 세션을 확인한 뒤 Script Cache에 90초 동안만 집계하며 시트와 감사로그에는 남기지 않습니다.
- 로그인 실패는 브라우저별·정규화된 접속 이름별·전체 기준으로 5분 동안 횟수를 제한합니다. 미등록·비활성·PIN 오류는 모두 `INVALID_LOGIN`으로 응답합니다.
- 일반 사용자 응답에는 접속 사용자 레코드와 PIN 해시·소금값·pepper가 포함되지 않습니다. 관리자 응답도 사용자 ID·접속 이름·활성 상태·수정 시각만 반환합니다.
- 설정·학급·학생·시간표·선택과목은 Script Cache로 조회하고 관련 쓰기 직후 무효화합니다.
- 원안 포장 링크 토큰은 소금값·비공개 pepper 해시와 버전만 Script Properties에 저장하고, 감사로그에는 대표교사·교무 담당자 이름 대신 비식별 세션 ID와 건수만 기록합니다.

## 관리자 설정 API

- `user_login`: `{ login_name, pin, client_id }`를 받아 `user_session`, `current_user`, 초기 화면 자료를 반환합니다.
- `admin_entry_login`: `{ password, client_id }`를 받아 사용자·관리자 세션을 함께 발급합니다. 접속 사용자가 없어도 첫 사용자 등록이 가능합니다.
- `save_access_user`: `{ id?, login_name, pin? }`로 사용자를 추가하거나 접속 이름을 수정합니다.
- `set_access_user_active`: `{ id, active }`로 접속을 허용하거나 차단합니다.
- `reset_access_user_pin`: `{ id, pin }`으로 숫자 4~6자리 PIN을 다시 설정합니다.
- `save_subject_catalog`: `{ grade, subjects[] }`를 받아 해당 학년의 교과목 목록만 교체합니다.
- `save_exam_notice_settings`: `{ notice: { year, semester, exam_name, greeting, notes[], issue_date, issuer } }`를 저장합니다.
- `get_admin_bootstrap`과 관리자 저장 응답에는 구조화된 `access_users`, `subject_catalog`, `exam_notice`가 포함됩니다.

## 고사 원안 포장 API

- `redeem_exam_packaging_invite`: `{ token }`을 원안 포장 전용 세션과 최소 공개 컨텍스트로 교환합니다.
- `get_exam_packaging`: 일반 사용자 세션 또는 원안 포장 세션으로 고사 제목·시간표 기반 항목·포장 설정·완료 집계를 조회합니다.
- `save_exam_packaging_items`: 항목별 `expected_revision`과 대표교사·답안지·포장일·시간대를 받아 한 잠금 안에서 충돌과 슬롯 정원을 검사합니다.
- `save_exam_packaging_config`: `expected_revision`, 설정, `preview_only`, `force`로 영향 확인과 강제 정리를 구분합니다.
- `create_exam_packaging_invite`: 관리자 세션으로 종료일을 지정해 한 번만 표시되는 링크 토큰을 발급합니다.
- `disable_exam_packaging_invite`: 링크 버전을 올리고 기존 원안 포장 세션을 모두 만료시킵니다.
